4. Vulnerable Code & Root Cause 2:00 - 2:40
👉 Action on Screen:
Switch to VS Code → Show app.js at Line 395. Highlight Line 397.
🗣️ What to Say:
"In app.js on line 397, we see how the search banner is built:
searchBanner = `... ${query} ...`

The root cause: The server directly concatenates unencoded user input into the HTML response. The browser cannot distinguish legitimate HTML from attacker-supplied script tags, so it executes the injected code."
5. Implemented Fix & Proof on Port 3002 2:40 - 3:20
👉 Action on Screen:
1. In VS Code, scroll up to Line 25 to show escapeHtml().
2. Switch to browser on localhost:4000 and click green button: "🛡️ Click Here to Send Same Payload to Hardened Server (Port 3002)".
3. Show Port 3002: No alert, balance safe, payload shown as plain text.
🗣️ What to Say:
"To fix this, on port 3002, I implemented HTML Entity Encoding using escapeHtml() on line 25. It converts the five dangerous characters—ampersand, less-than, greater-than, double quote, and single quote—into safe entities like &lt; and &gt;.

Now when we send the exact same exploit to the hardened server on port 3002, no alert fires, the balance is untouched, and the payload is rendered as harmless plain text. The attack is completely neutralized."

🗣️ What to Say:
"Finally, from the lecture slides, the other mitigations for XSS are:
1. Framework Auto-Escaping: Frameworks like React or Handlebars encode output by default.
2. HTML Sanitizers: Libraries like DOMPurify strip dangerous tags if rich HTML formatting is needed.
3. Content Security Policy: Setting a script-src 'self' header tells the browser to block inline scripts.
4. HttpOnly Cookies: Prevents JavaScript from reading session cookies via document.cookie.
